Base: Comet main 68527ee. Read docs/plan.md, docs/port-victory.md, patches/notes/evidence-cell-999243c.md. Reference: Belobug/VIctory-Belobug-AMD 4cbe9d7 and fxceless/victory-fork 0b0074e, GPL-3.0-or-later; VIctory by Marvisak and contributors, fork changes by Belobug and fxceless/hyphennn respectively. Static comparison, not a port of reference code. No game build/run.

## Evidence and findings

1. **All-known-copy amplification.** fxceless crates/victory-gpu/src/memory.rs:293–313 registers every numbered shadow on first read/write of a list. Comet crates/comet-gpu/src/memory.rs:321–355 preserves this and corrects coverage when other lists introduce copies; :158–180 keeps an ever-growing vector and publishes whole pages, :235–237 maps a second 4 MiB window. Comet shadow.rs:2308–2310,2350–2369,2380–2414 explicitly declares refresh and potential writeback of each entire shadow; non-in-place writes snapshot and compare even if a shader touches only one word. Explains potential prepare 4256 ms/readback 2681 ms amplification; exact attribution requires bytes/list and timing. Never revert L2 coverage or infer a write set from root pointers alone.
2. **Directory copy cost.** fxceless memory.rs:278–318 binds a live directory (known shortcut). Comet memory.rs:305–306,360–367 + host.rs:5948–5969 snapshots the directory per recording list/heap and copies it again when its epoch changes. emit/shader.rs:38–51 MEMORY_PAGES=2^21; 8 bytes per entry = 16 MiB per actual memcpy, not per dispatch if epoch unchanged. memory.rs:199 advances epoch for each successful mapping. This is CPU recording/prepare and memory-pressure candidate, not proof of readback cost. Retain list isolation and heap publication ordering; a shared mutable directory is not a safe optimization.
3. **Reference architectural difference.** Belobug crates/victory-gpu/src/memory.rs:21–25,49–64,94–129,133–154,159–213 uses an 8 MiB directory of 1 MiB entries spanning 40 bits, sparse 2 GiB chunks and preferred in-place windows, incrementally publishes descriptors and restores sparse mapping on remap. Comet memory.rs:60–79,122–199,305–355 instead owns Arc<Shadow> per numbered copy and has whole-window refresh/writeback. Existing Comet shadow.rs:2360–2367 already bypasses copyback for placed memory but warns aliases are not notified. Porting sparse/in-place architecture requires N6 alias/physical-page guards, residency, remap, fencing and translator ABI work; not safe as a single M7 switch. Belobug is a cost design reference, not proven RT-correct.
4. **Candidate alias bug, NOT proven bad writer.** Belobug memory.rs:112–127 overlays in-place windows atop sparse backing and :133–154 handles remap. Comet memory.rs:129–133 never reconsiders a populated entry, :165–178 explicitly shortcuts separate buffers within a mapped window. Thus raw address and root/descriptor views can name different copies. fxceless memory.rs:119–195 has the same first-wins shortcut. This could return stale pointer or AABB bits; need actual source address, shadow IDs, mapping generation and ordered submissions before changing mapping. Coordinate N6 and L2.
5. **Writer unresolved.** G3 #31 comment 7160929533 quotes real execution log "the ray-tracing structure builder runs: all of its programs have host pipelines (52)" then RAX=0x7f800000101a3900. High dword is +inf as f32, RAX is a value not source address. B5 #31 comment 7160724268 references faulting fork builder 5552dac6a2b7a1fd and 72e748e atomic fences; neither is proven Comet writer. fxceless docs/fork-ray-tracing.md:3,59–69 explicitly says nothing lit by RT and builder remains disabled in real run. Comet evidence-cell: quarantined builder runs 315s, 9 drops/frame, 0.12fps and later white. White is consistent with nonfinite propagation but not a measured first bad buffer. Do not clamp NaN, suppress stores, or treat quarantine as correction.
6. **Safe local cost candidate:** Comet memory.rs:347–355 still visits every copy even when coverage watermarks say no new work. With COMET_M7_RAW_MEMORY_COST=1 start iteration at min(read_start, write_start if writes else copies.len()); both original predicates retained. This is exact registration-set equivalence, only reduces CPU scan work, not the expensive full-range transfer. Add diagnostic count/bytes of refresh/write declarations and snapshot copies; compare timings. Reference fxceless memory.rs:293–309 has the same full scan. No reference code port; no credits code change necessary. No claim that this fixes seconds of cost.
