# G6 cutscene readiness follow-up

Benchmark-owner observation: opening gas station cutscene before yard stays blocky, flat-coloured, blue-washed for whole shot at ~0.5 fps; retail resolves within a few frames. Streaming now priority; geometry and texture readiness must be distinguished. No capture yet attributing the actual LOD bit, draw or source asset. Source audited eb5ab732; companion patch based on 905a9608.

## CPU completion contract, exact calls

crates/comet-hle/src/modules/dstorage.rs:
- :153-176 CreateStatusArray initially stores S_OK; :294-305 status_result Acquire and IsComplete != E_PENDING. Source comment: title polls entry 0 in Sleep(1) loop and never reads the result. STATUS_VTABLE :308-314 IsComplete at 0x18 and GetHResult at 0x20.
- :791-812 EnqueueRequest and EnqueueStatus (queue vtable :1139-1146 slots 0x18/0x20); enqueue status writes E_PENDING Release before queueing. :815-846 queue holds commands unsubmitted until half capacity, or :848-860 explicit Submit (slot 0x30). :559-587 assigns sequence numbers and publishes submitted commands to workers. No frame/present dependency in these functions. Fence signal slot 0x28 and error event slot 0x48 are unimplemented; this is not evidence title calls either.
- :455-475 worker executes actual I/O/decompression and destination write, then locks lanes, finishes request, wakes workers and waiters; :547-556 removes running sequence and records failure; :611-629 Lane::flush waits for ALL earlier submitted reads in that lane, not other lanes or a GPU fence, then publishes first failure or S_OK Release. CPU polling Acquire sees completion. Status can be delayed by one earlier slow request, staging cap, head-of-line selection (:516-545) or underfilled queue awaiting Submit, but there is no per-render-frame completion throttle in HLE. A title thread might enqueue/submit or consume results per game tick; cannot infer without timestamps.
- Failure is terminal from HLE's viewpoint: IsComplete returns true for any nonpending HRESULT including E_INVALIDARG and E_ABORT. At :1121-1134 a failed physical write explicitly logs destination unwritten. No automatic retry; title retry not known; queue-close cancellation also publishes E_ABORT (:645-676). Do not claim completion equals resident mesh. Do not fake S_OK or turn errors into indefinite E_PENDING.
- Request layout :680-699 includes file offset, sizes, page list or virtual address and tag (comment title leaves tag 0), no mesh/LOD metadata. There is no host-side semantic LOD flag in this path. Actual title-owned ready bit/asset handle is unlocated; need correlate successful poll to CPU metadata write, or GPU descriptor/meshlet-args change. Source does not prove title's exact post-poll code. References share poll design: Belobug dstorage.rs:284-296,596; hyphennn :286-298,693; DexNom :286-298,645.

## CPU ready but GPU not ready

- dstorage.rs:1086-1134 virtual destination calls kernel_will_write before fill. Physical page destination fills through private mapping (xmem.rs:544-590). watch.rs:18-22 explicitly does not observe such writes at guarded aliases. GPU Shadow::refresh (shadow.rs:2308-2311) defers until list submission; copy_stale (:3104-3136) copies only new epochs, so a resident title page can contain new mesh bytes while the host copy continues reading old data. N6 #104 already owns alias_physical_written/alias_write_complete. Need correlate mapped guest span to actual mesh SRV; not enough to see physical_dirty > 0.
- Texture availability is a separate host queue: descriptor/host.rs:372 remapped, :629-641 texture_tick/queue_clock now 33ms wall-clock; :1015-1063 due/recheck/later and :1184 queue_texture. draw.rs:2022+ services this queue; even with wall-clock deadlines, actual sweeps still need host work. N5 owns texture readiness; ask whether high detail never arrives in guest pages or host slot remains null after a successful request, not to use texture mip status as mesh LOD proof.
- The GPU culling reference hashes remain candidates: 1c4b3c0547e3e6fa slod (may be static super-LOD), 9146291b38ea9ce1 meshlet_args. No character/car selector or readiness bit confirmed.

## Which log shows what

Existing g6-lod-trace patch blob f35d6ce5dfb409af279db66c4cfcb5dcd15fcb95: all eight original hunk old sides matched exact source lines on eb5ab732; no rebase required at audit. G6 LOD direct dispatch status and G6 LOD indirect dispatch ran only identify compute producers; neither labels stand-ins or measures executed primitive count. frame-<n>-ops.txt includes draw/indexed counts, mesh groups, shader hash, bindings, and with that patch indirect stride/count addresses (draw.rs:2413-2473,2492-2510,3010-3034,3114-3135,3351+). Indirect max is capacity, not count. Mesh group count is not triangle count. Captures use presented()+1; producer log frame::current is a frame token, not guaranteed same numbering.

Companion patches/g6-draw-evidence.patch.txt (base 905a9608, blob 4fb76b5b85b6da58485667f6a240cceb0cd2ef5d) independent default-off COMET_G6_DRAW_EVIDENCE=1 adds literal "G6 geometry topology" to recorded graphics ops; title VB slot/address/length/stride, IB address/length/format, first 48 dwords per graphics root constants slot, direct draw first/base/instance and original title vertices for expanded rectangles. Includes test g6_ia_text_keeps_slots_and_guest_ranges. Bound IA views may be unused/stale in mesh pipelines; use translated SRV bindings for mesh draws. No GPU readback or LOD label. Match same object by depth region, shader/instance/binding ranges and actual draw records; no stand-in/full label until matched. M2/N4 need actual indirect args/count and meshlet output counts if required.

## Capture request

Use diagnostics and baseline settings; COMET_CAPTURE=<dir> COMET_CAPTURE_WORLD=1 COMET_CAPTURE_WORLD_ALSO=8,16,24,40,48,56,64,72,88,96 COMET_DUMP_TARGETS=1 COMET_G6_LOD_TRACE=1 COMET_G6_DRAW_EVIDENCE=1 COMET_STREAM_STATS=1 (N8 staged switch when available). Default capture already includes +2,+6,+30,+80 and saves PNGs every 8 frames; first 500 draws marks opening cutscene, not prison. Extra frames sample early and late gas-station shot; if shot differs pick matching image by visual timeline. DUMP_TARGETS can perturb throughput, so use same diagnostics on matched runs and limit extra offsets if too expensive. Keep N6 alias switch if already on card, note exact settings. Request N8 timestamped enqueue/submit/start/finish/status publish and first observed poll, lane+sequence+status array/index+generation, hr, source offset, virtual destination or page IDs/offset; avoid logging every pending poll and tag-only joins. Ask N5 for texture generation and null/mapped/uploaded counts at same times. Use common elapsed wall time and presented frame where available; don't equate token to presented frame.

Discriminators: pending before cut -> CPU delivery/submission lag; completed failure -> missing data, retry unknown; completed S_OK + guest mapped + unchanged GPU range -> stale publication hypothesis; completed and correct GPU data + unchanged actual selection -> investigate title metadata/cull; high geometry detail but flat colour -> texture/lighting, not mesh LOD. No corrective LOD patch until capture locates the gate. Existing N6 patch is candidate correction, not a G6 confirmed fix.
