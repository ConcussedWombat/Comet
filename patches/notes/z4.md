## First, one independently testable idea: small buffer residency
User baseline ~1 FPS, prepare ~160 ms, GPU wait ~600 ms, readback ~100–170 ms/frame. No Z4-specific shader hash in supplied data; this is a host-buffer placement/hash mechanism affecting many passes. Upstream c36971b README reports same-draw-count runs 274/275 on RTX 4070: title lists 68.0 -> 49.8 ms, own send/hash lists 11.6 -> 23.0 ms, frame 114.9 -> 109.7 ms; short hashes were not game-tested there. Do not extrapolate those timings to RTX 5070 Laptop or claim a measured Comet win.

### Benchmark / rollback
Fresh process each trial, same scene, shader cache, switches, camera/draw counts and duration. COMET_CARD_BUFFERS=0 disables entire preexisting path, not a baseline for this patch; instead unset new switches for control. Test hash-only (COMET_CARD_HASH_LEN=1), then min=1024 with hash=1, then 256, then 64 if texture budget and visual score permit. A placement-only run (hash unset) isolates costs if time permits. Do not copy upstream 1280 MiB cap onto an 8 GB GPU. Small copies are rounded to 64 KiB: 3700 * 64 KiB alone would be ~231 MiB committed, not the ~30 MB logical size upstream reported. Cap can prevent placement and earlier small allocations can compete for non-priority large buffers; record fallback counts and texture waiting. If regression, revert both switches; no persistent cache state.
- Engagement: "Z4 card buffer policy" with minimum_kib, cap_mib, logical_hash; "a buffer's host copy is in the card's memory" includes len and guest start. Check actual small allocations, not only the policy marker.
- host.rs:6850–6890 COMET_BENCHMARK wait_us/readback_us per sample frames; "our passes over copies in the card's memory per frame"; "internal GPU memory passes per frame: ... uploading/rehashing, ... comparing" (diagnostics COMET_GPU_TIMING); "card readback per frame". shadow.rs:1774–1780 "CPU-scanned buffer MiB/frame by VRAM fallback reason" (below_min vs budget/cap). Compare title pass timing as well as aggregate wait and copy-back. Target reduce below_min scanned bytes and PCIe shader access; 5–20 ms/frame is only a hypothesis for gate, not a prediction of reaching 10 FPS. Report texture waiting, VRAM headroom, device errors, black albedo and matched cell/boat captures. Stop if either renderer score or FPS regresses.
