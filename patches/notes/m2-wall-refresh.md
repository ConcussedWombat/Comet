## Where stale alias writes are missed

1. watch.rs:1–21 explicitly describes per-VA dirty bits / 64KiB guards and missed writes through another view (runtime physical writes, DirectStorage destinations). record_writes:387–399 stores virtual page keys; wrote:301–310 reports only supplied VA. A write at alias B does not age A's epoch. asked/writes:407–443 can return prior journal or clean guard evidence without reading the bytes. guard:647–671 protects the requested block, open:839–854 removes only the written VA block from clean/protected. Handler:1101–1120 receives fault VA; if B was not protected, no fault, and even if B was protected it opens B rather than A. writing:860–865 and remap/alias reuse:1043–1070 likewise operate on given VA. N6 owns fix; do not duplicate.
2. shadow.rs:3434–3479 selects buffer/window by title VA range, so two virtual aliases can have independent shadow identities. Physical alias identity not represented in copied epochs: shadow.rs:3094–3125 compares watched page epochs to copied page epochs; missed writes retain old data. shadow.rs:2979–3014 skips pending GPU-write ranges; zero bytes copied can mean in-place, busy range or journal clean, not proof of staleness. GPU producer writing different host copy also requires correct visibility/copyback, not just CPU guard. N6 to inspect pending overlap.
3. Host list defer_refresh host.rs:5861–5874 deduplicates same range per list; Batch add/update/flush:6346–6437 merges spans and checks at submission. watch ask_ahead/ask_once caches VA-based answers. Actual bytes copied at shadow.rs:3129–3138, CPU staging marked dirty for card copy 3147–3160; host.rs:4927–4950 flushes before card_before upload and submits. A scheduled refresh is not an upload or proof of fresh contents.
4. Independent of physical aliasing, draw.rs:1818–1835 once-per-list/frame gate explicitly admits inter-list writes seen one frame late. draw.rs:1910–1941 historical stale streamed geometry; COMET_UNWATCHED_FRAMES>1 can further throttle. Do not change cadence before measuring. A missing descriptor (M1) is another mechanism.
5. Reference: Belobug ae90937 watch.rs:225–326 physical section+offset to view map, 519–558 guard/open all aliases, 612 kernel writing; more than 64 aliases special case. Hyphennn 8dd30ab watch.rs:411–559,647–688 analogous shared-view guard/open; commit reports 0.8–1.0M alias writes in 5 min on RTX4070, README reports walls 4/4 later runs vs 2/5 before, first shot still sometimes absent. Reference not Comet measurement. Credit: VIctory by Marvisak and contributors, fork changes Belobug / fxceless; hyphennn credits myokex c6dc4d8, Spexivus, joroyt, tightfall. ## Staged diagnostic

patches/m2-wall-refresh-trace.patch.txt, COMET_M2_WALL_REFRESH=1 (default off), revision a8357ed, blob 8726ec15d51a5c15f7b27ee39f0c8539044f984d. Selection: all depth-bound indirect mesh candidates, known M1 indexed/nonindexed depth candidates, selected direct and indirect culling dispatches. Not claiming every candidate is a wall draw: match depth target/scissor/hash from capture. No changed resource binding, guard, count, submission ordering or refresh cadence. Unit test selection predicate; not built/run, exact old hunk context verified. No shader changes/cache key.

Log join:
- "M2 wall indirect candidate" draw ID, recording frame, pipeline, depth handle, scissor, args/count, stride/max. "M2 wall indirect recorded" = command recorded, NOT GPU executed. "M2 wall argument backing" shadow IDs/window hit.
- "M2 wall shader stage", "M2 wall indexed binding" hash, exact selected table handle/range (null if not resolved), dynamic_heap/raw_memory flags. "M2 wall table buffer", "M2 wall root buffer"/"M2 wall root SRV table"/"M2 wall root UAV", "M2 wall IA vertex buffer"/"M2 wall IA index buffer" identify actual paths and range/ID. Scratch CBV is not a shadow upload.
- "M2 wall refresh request": draw, recording frame, copy ID, address/len, queued vs deduplicated, last_copy token (any range of that copy, may predate request), carded/in-place. "M2 wall bulk heap refresh" reason scheduled or skipped. Broad heap ranges deliberately not misattributed to each draw; raw directory candidates may be conservative.
- "M2 wall refresh result" submission-time frame token, copy ID, span, copied bytes; "M2 wall bytes copied" exact CPU staging subrange for marked shadows. Join by copy ID, intersect ranges, compare recording/submission token (can differ, neither alone is GPU frame). A zero result is no CPU copy in that span, not necessarily stale; a nonzero result or last_copy does not guarantee full requested range, mapped content, or GPU card upload. Exact subranges logged after first selection, earlier copy token only. In-place no copy expected. No CPU reads forced, no data dumped. GPU-side writes and dynamic bindless indexing need GPU capture.
- On capture, test off/on (same camera/mip/ambient/builder), with and without N6 COMET_ALIAS_VIEWS once staged; keep indirect windows off to remove speculation. COMET_CAPTURE=<dir> COMET_CAPTURE_WORLD=1 COMET_CAPTURE_WORLD_ALSO=120,300 COMET_DUMP_TARGETS=1. Collect matched wall-present and missing-wall frame depth handle + screen region and per-draw ops. For each candidate identify actual shader-read buffer ranges (including GPU-computed indices), count/args and producer UAV, match M2 shadow IDs and N6 physical alias journal; compare CPU shadow and GPU resource contents at consumer. Report missing depth wall/ceiling, FPS, device errors; diagnostic overhead expected, not perf measurement. If count=0, trace producer cull inputs first; if nonzero and stale input, correlate alias writes; if all buffers current, investigate null binding, shader execution, bounds/frustum, depth/scissor.
