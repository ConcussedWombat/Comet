COMET_FPS_COUNTER defaults ON as explicitly requested by benchmark owner (exception to docs/plan.md default-off convention). Set =0 before launch to bypass sampling and copies. Starts with -- FPS  -- ms, first measured label appears on the next present after the first >=500 ms interval window. At ~1 FPS the label can only refresh as new frames arrive; no background thread or claim of 2 visible updates per second when the title presents fewer. FPS is successful host Present rate, not scanout/GPU timestamp. Example 2.3 FPS  434.8 ms; both computed from the same unrounded interval window.

## Evidence and acceptance

Expected once per presenter: `Z1 FPS overlay recorded (500 ms samples, host back buffer only)` with width, height, pitch, format. This proves recording, not execution. Capture the displayed window in cell and boat with unset/0 and compare; no change in title or internal W5 capture pixels, no new device errors, no meaningful FPS regression. Repeat with COMET_LATE_WAIT=3 and resize/format change; verify no D3D12 lifetime or copy-state errors. A failed allocation skips the label without affecting Present. Existing benchmark meter untouched. Unit tests cover 500 ms cadence, 1 fps, glyph bounds and swap formats; build/tests/runtime not run per worker constraint.
