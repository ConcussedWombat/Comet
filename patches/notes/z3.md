## Staged slice

One bounded group (8 parts / 48 lists maximum) of already-ready same-queue Held::Run entries; no new asynchronous admission or recording. Only intervening Value waits already met in title memory may be consumed; fences, signals, forced drains, W5 ordered present drain, unready waits and GPU_TIMING are barriers. Both preceding and incoming parts must have no bottom-of-pipe writes, raw-memory writes or texture readback, and only read-only Refresh / list-owned Fill steps. Reject Copy, GpuWrite, Run, Host, Texture. No assumptions about overlap through aliases of a write: no admitted title/GPU publication. This is deliberately narrower than upstream; may engage rarely. Batch can coalesce refreshes as within one submission; each original ExecuteCommandLists call boundary and list order is retained, including preludes and last compare. One final fence/settle, one lifetime flight when existing late mode on. Original Detached ownership stays with queue until recycle or flight landing. No mutation to W5 admission or descriptor sync at queue entry. Normal no-switch path submits the same list groups. No GPU timing joining (avoid changing timing attribution).
 
## Full async worker recipe — NOT staged yet

1. Preserve W5's admission sequence (queue.rs 147, 620, 724, 751, 867) in a single sequenced lane. Transfer *owned* Detached lists and QueueRef/FenceRef, never a borrowed This pointer or raw caller list array; hold releases in FIFO, maintain bounded pending runs / presents and failure wakeups. Use Z2's recording completion at the detach boundary, not a second recording pool.
2. Keep descriptor::sync_heaps on admission until a captured descriptor generation can be guaranteed; moving it arbitrarily to preparation can expose the next submission's records. Before the worker returns control, any title-memory Fill/Copy/Run or raw texture readback must remain synchronous or own exact data and destination lifetime. Current Host::execute_late explicitly forces raw readbacks synchronous at 4588-4599. Upstream 18c0129 (VICTORY_SEND_OWN) documents the shared upload overwrite hazard; do not bypass it.
3. Host::retire currently uses STARTED/FINISHED only; a job queued but not STARTED is invisible to retirement. Introduce reservation IDs before enqueue, ordered completion including canceled jobs, and resource retention through publication (not merely GPU completion). Preserve FenceRef in queue and flight signal jobs. Drain sequenced eligible work before fence event waits, synchronous Host::execute, title readbacks/page mappings, and present. Worker must not drain itself or acquire W5 admission while caller awaits drain. W5 present must still publish all preceding flights, release ready parts and copy the current source in admission order; do not replace with upstream's free present mode. Existing relay is default off (host.rs 2210–2355), so upstream worker's prerequisite is not met by default.
4. Broader joins: port refresh_front and range-based joinable only after CPU/GPU write publication and per-submission upload snapshots are proved. Include tests for pending release before STARTED, wait/signal order, W5 0/30 backwards presents, readback lifetime, source buffer mutations, alias writes, worker panic/queue pressure, and repeated indices. Do not enable Relay just to obtain an FPS figure.

## Build/benchmark gate

Added pure unit tests for order/part offsets and caps, and conservative Deferred admission. Not built or run by Z3. Patch generated from exact pinned source anchors; build gate should run cargo tests for z3 and existing serial GPU lib tests. Test switch off first, then on (same scene, same late/relay settings; first default late off); do not combine with Z2 initially. Log `Z3 joined submission parts (COMET_JOIN_PARTS)` frame/candidates/joined every 32 frames; zero candidates or zero joins means no demonstrated benefit. Compare host submissions/frame, prepare ms, GPU wait ms, copyback ms, FPS, missing textures, device errors, W5 forced runs/order, and matched cell/boat captures. Reference 160 ms preparation + ~600 ms GPU wait + 100–170 ms copyback: the broad upstream 28 ms saving is not a prediction here. With 0 joins expect no gain; measurable nonzero joins should reduce duplicated preparation/waits without worsening rendering, but size unknown. For matched captures use COMET_CAPTURE=<dir> COMET_CAPTURE_WORLD=1 COMET_CAPTURE_WORLD_ALSO=120,300 and COMET_DUMP_TARGETS=1. Z2 coordinated on #140: recording before detach, no changes to recorders here.
