## Single idea and boundaries

`COMET_Z12_STORAGE_EXPLICIT_SUBMIT=1` (only literal 1; default off) waits for explicit Submit instead of half-full auto-submit. Keep the upstream deadlock escape: if an enqueue cannot make room and no submitted reads are queued/running but unsubmitted commands exist, submit that batch; warn on fallback. If existing submitted reads can make room, wait on existing condition variable. Do not flush early merely because total occupancy is high. Explicit Submit keeps original ordered status/sequence/worker behavior. No page-list reread, retry, change to HRESULT, alias/descriptor writes, shader changes, thread priority, VRAM allocation, or texture mip policy. Default runtime branch retains previous half threshold, no Z12 logs when off. New markers: `Z12 DirectStorage explicit submit` (queue, command count), `Z12 DirectStorage capacity fallback` (queue, command count, warning). Markers requested, not yet seen in a live run.

Risk: title/other callers could rely on half-auto-start before explicit submit, and a genuinely full unsubmitted batch may still start before page-list population. Fallback preserves enqueue liveness, not correctness of such a batch. Watch stalls and fallback count; do not claim universal DirectStorage contract or fix all errors. Switch off if regressions. Larger batches may temporarily reduce overlap and throughput. Logging per explicit batch adds opt-in overhead. Same source function touched by N8 stats patch near :838; integrate counters before the policy condition, keep original cancel/ref ownership and N8's status reporting. I2 coordinate if both land. No direct source edit.
