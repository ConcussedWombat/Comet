# B5 — VIctory-Belobug-AMD rendering survey

Issue [#81](https://github.com/Fyntra-Development/Comet/issues/81); Coordination [#44](https://github.com/Fyntra-Development/Comet/issues/44). Survey only, no production code changes, no build or runtime claim.

## Phase 1 — Texture memory and residency (P1, supersedes earlier visual hypotheses)

Updated after [plan.md at 8911655](https://github.com/Fyntra-Development/Comet/blob/8911655/docs/plan.md). **Measured, not conjecture:** walls/floor/ceiling/bunks/characters exist in depth and normal G-buffer; RT0 base colour is zero on 81% of drawn pixels. Indexed textures 263 at world start → 19,856 (6.4 GB) after 2 min → 12,700+ waiting indefinitely. 8 GB GPU vs console 16 GB unified. Alpha-tested objects disappearing remains a hypothesis. Targets: <10% zero albedo, ~0 waiting, <50 drops/frame, 5+ FPS. Ambient is Phase 2 and cannot recover missing albedo. The earlier survey's geometry and indirect-light hypotheses are retained below as historical leads for later phases, not the measured primary cause.

### Immediate recommendations, with current Comet source evidence

1. **Remove duplicate copies without lowering quality first:** upstream [13bbd6f](https://github.com/Marvisak/VIctory/commit/13bbd6f) by Marvisak and contributors (commit login Marvis), then combine with fork [4284939](https://github.com/Belobug/VIctory-Belobug-AMD/commit/4284939) by Belobug. Upstream shares compatible host texture memory by layout/shape/address; fork normalizes description padding (word 1 zero; word 13 actual largest mip), accounts for smallest-first allocated reach. The fork says padding alone made the same texture up to four times. In current Comet main, `resource.rs::texture_at(address, desc)` at ~2057 keys the raw 14-word description; `let_go_idle` at ~1431 evicts only if the texture and descriptor references are gone. Do not simply merge by address or format byte width: check normalized resolved layout, range, mips/planes, array/cube shape, swizzle, generation and compatible DXGI cast family, usage flags, samples, and GPU-written vs title-filled ownership. Upstream shortcut keeps old descriptor slots after replacement; fix with generation/versioned rebinding before reusing storage. BC remains BC; verify allocation info and format counters, not just requested byte estimates.
2. **Mapped mips and memory pressure are separate:** [4284939](https://github.com/Belobug/VIctory-Belobug-AMD/commit/4284939) implements actual allocated/view mip reach; [ebd990d](https://github.com/Belobug/VIctory-Belobug-AMD/commit/ebd990d) adds *quality-reducing* cap for streamed read-only BC 2D textures only, max dimension 1024 at <70% local budget usage, 512 at 70–84%, 256 at >=85%; override VICTORY_TEXTURE_MAX. At tip `resource.rs::over_cap` and `texture_at` combine pressure skip and largest mip. Cap policy applied at allocation is not full resident LRU; existing copies don't necessarily shrink. Adapt as opt-in pressure relief with hysteresis, per-allocation byte accounting, versioned upgrades/downgrades and demand priorities. Do not cap RT/DS/UAV, nonreconstructible copies, single-mip resources, or silently alter logical LOD/GetDimensions/Load semantics. Fork skips certain copies involving truncated textures (shortcut); Comet must handle or explicitly exclude those resources. Verify actual mapped intervals per slice/mip/tail; total committed bytes alone cannot prove all bytes of a particular mip are valid. Publish view only after upload completion/order.
3. **Evict by draw demand, not reference existence:** Comet `resource::room` permits 2 GiB floor then <90% current DXGI process budget (4 GiB fallback, COMET_TEXTURE_BUDGET_MB override); `let_go_idle` requires 5 s + 4 frames, title-filled and not host-written, Arc count 1 and D3D texture reference count 1. Live descriptor slots therefore pin otherwise cold textures. Fork [00fc4a7](https://github.com/Belobug/VIctory-Belobug-AMD/commit/00fc4a7) eviction is on overlapping unmap/remap; [e136a55](https://github.com/Belobug/VIctory-Belobug-AMD/commit/e136a55) and [fd3b8ce](https://github.com/Belobug/VIctory-Belobug-AMD/commit/fd3b8ce) LRU is **staging/upload heaps only**, 1 GiB originally then 384 MiB at tip; it sorts by use, only map-held buffers, trims toward 75% after crossing budget. This is NOT evidence fork implements true VRAM texture LRU. [7dddec2](https://github.com/Belobug/VIctory-Belobug-AMD/commit/7dddec2) retires slots/textures only after in-flight submission completion (freed BC7 GPU fault is explicit negative evidence), [a873b24](https://github.com/Belobug/VIctory-Belobug-AMD/commit/a873b24) pooling safety. Need Comet-specific cold sampled texture LRU: maintain actual-use recency (including indexed binds, conservative possible-use sets for unknown dynamic indices), retire only reconstructible title-backed copies after fences, invalidate generation and requeue all aliases; never release host-written/RT/DS/UAV or in-flight bindings. Descriptor heap versions must preserve pending command-list semantics; no raw reference-count bypass. Use pressure-targeted low/high watermark and observe actual committed bytes after fence retirement; no unbounded retries.
4. **Draw-first queue:** Comet `draw.rs::heap_textures` (~1871) already has 192 MiB/frame and 250 ms default per-pass CPU allowance, due list up to 4096, remap invalidation and partial-byte tracking. It emits `textures picked by index: the card has no room for more; they wait`. Fork [beffaea](https://github.com/Belobug/VIctory-Belobug-AMD/commit/beffaea) force-prepares up to 2048 newest slots to avoid high-index starvation, [efc045e](https://github.com/Belobug/VIctory-Belobug-AMD/commit/efc045e) time budget, [7afcbff](https://github.com/Belobug/VIctory-Belobug-AMD/commit/7afcbff) changed slots; none proves actual current shader demand. Prioritize known current draw table entries, then conservatively demanded bindless slots where evidence exists, then age/fairness/background. Unknown GPU dynamic indices cannot be inferred from root constants alone; use real sampled-index instrumentation if needed. Requeue on remap, rematerialize after eviction; never use waiting-slot count decrease caused solely by evicting/nulling or suppressing requests as visual acceptance.
5. **Account exact memory:** [6e2a299](https://github.com/Belobug/VIctory-Belobug-AMD/commit/6e2a299) format/shape/mip/flags census, [bb1d5d6](https://github.com/Belobug/VIctory-Belobug-AMD/commit/bb1d5d6) real allocation bytes, upstream [13bbd6f](https://github.com/Marvisak/VIctory/commit/13bbd6f) total vs GPU-used and shared/saved/replaced counters. Break down BC formats, RT/DS/twins, sampled object vs placed vs shared allocation, staging upload, readback, buffers/tiles, descriptor retention, retired-pending, actual DXGI local/nonlocal budget/usage. [3afed01](https://github.com/Belobug/VIctory-Belobug-AMD/commit/3afed01) large buffers in VRAM can compete with textures; [9956958](https://github.com/Belobug/VIctory-Belobug-AMD/commit/9956958) disabled unsafe sparse tile sweeps after GPU fault. Do not improve one counter by moving everything into system RAM or dropping draws.
