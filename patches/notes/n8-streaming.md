# N8 — opening-cutscene streaming

## Evidence and scope

Benchmark owner observes opening gas-station cutscene at ~0.5 FPS, lowest LOD/flat untextured color, blue wash, never reaches full detail before cut. Seven warnings per run: `dstorage: a destination's physical pages could not be written (unknown page or a host failure); its request fails`. No source range, page ID, title resubmission, or actual per-second throughput was supplied yet. No HLE shader hash applies. ## Existing completion path (current source lines)
1. dstorage.rs:815–859 queue() accumulates commands and auto-submits at half capacity; submit() explicitly moves pending commands to lanes and wakes the worker pool. No frame API. A sparse queue can sit unsubmitted until title Submit; this is distinct from a completion issue.
2. 455–475 work() starts jobs, drops scheduler mutex, executes file read/decode/physical publication, then reacquires lanes and calls finish. scratch.finish() precedes that lock. Worker calls notify_all on finished; staging waiter wake follows freed space.
3. 547–556 finish() removes sequence from running and records any HRESULT; invokes lane.flush().
4. 611–630 flush() publishes the next status once every earlier read on that lane has retired, with first prior failure or S_OK, via Release atomic store. No present/fence/event/frame callback. A long earlier request can delay a later status even though a later read finished: required ordered status semantics. Do not bypass it.
5. 294–306 status_result() uses Acquire atomic load; is_complete() tests != E_PENDING. Source comment says title polls entry zero in Sleep(1) loop and never reads HRESULT itself; this is prior code attribution, NOT a live measurement of every cutscene. The title might submit or consume statuses only on a game-thread update, but no HLE frame boundary is present here.
6. 1086–1133 into_destination(): direct physical page window, otherwise buffer then xmem::write_physical(); failure returns E_INVALIDARG. xmem.rs:519–560 unknown page/table range or host MapViewOfFile/commit failure; a multi-run copy may already have partially written before a later run fails. Never mark a failed or partial write successful. A failed status cannot by itself prove the content is permanently lost.

No frame-gated completion fix justified. Stage n8-stream-complete.patch.txt as TEST ONLY (no runtime behavior, no switch necessary): submitted_status_is_published_without_title_polls_or_frames waits on the worker's condition variable, observes status with Acquire directly (no title status call or render), then verifies the actual data. Existing a_status_waits_for_every_earlier_read covers ordering. If it fails, investigate the worker/status path before changing semantics. No game/build/test run by N8.

## Telemetry: n8-stream-stats.patch.txt
COMET_STREAM_STATS=1, default off. Reporter begins after scheduler starts and logs approximately every five wall-clock seconds, including idle intervals; prints actual spawned worker count, not hardcoded 24. Separate counters for enqueue/submit/completed (includes errors)/successful/failed/canceled (submitted reads dropped on queue close). Source bytes from actual file seek_read progress; output bytes from successful fill/publication (partial failed writes not counted as successful). Snapshot unsubmitted, submitted waiting, running, status queue, staging bytes and limit; busy count, peak and time-weighted mean integrated across worker start/finish. Queue snapshot and rates taken sequentially, so can differ slightly in a racing window. Histogram is submit-to-worker-finish, floored 1 ms bins; >=10 s bucket capped at 10000, reported separately. Empty histogram None. Not device IO-only latency and not status-to-title-observation latency.
- `N8 stream stats` rates/depth/worker count/percentiles.
- `N8 stream completion and retry stats`: status poll and publication rates, failed statuses, repeats and unmatched ranges. `N8 stream file stats`: synchronous ReadFile/fread calls and returned bytes, failed synchronous ReadFile, short fread (may mean EOF), overlapped calls counted but their eventual completions/bytes not observable here. Do not add CRT and DirectStorage bytes as total disk IO; caching and layer overlap possible.
- Failure `N8 stream physical destination failed` includes seq, source offset/sizes/options/name, page offset/len, first 64 page IDs and total count. xmem `N8 stream unknown physical page` reports exact first offending page, table count and next allocation number; `N8 stream physical run mapping failed` reports host MapViewOfFile error (commit logs existing host error separately), section/run indices and up to 32 intersecting guest virtual ranges with total alias count. `N8 stream physical copy stopped` reports first page in failing run and bytes already written. Logs have sequence correlation when called by a worker; temporary in-place attempt failures may recover on fallback, so count final request failures, not all probes.
- `N8 stream file request failed`, `N8 stream same file range resubmitted`, `N8 stream repeated file range succeeded`: exact stable file path + offset + sizes + options/intermediate length after earlier failure. Destination can change. At most 4096 outstanding identities; overflow counted; same-key later failure replaces prior ID. Memory sources have no stable identity and are explicitly untracked. Case/path aliases or split/merged retry reads may not match. Repeat success is evidence of same range reread, NOT proof that title consumed it; unmatched at end = no observed matching retry, NOT permanent loss. No retry or success fabrication. Actual host errors and page lists required from capture.
- Disabled path: no reporter, no stats mutex, no histogram allocation or failure logging; only cached switch branches/optional fields. Opt-in telemetry itself adds locks and logging, so compare overhead with stats off.

## Capture request and decision
Same profile, cache warmth, launch settings and camera from gas station through prison yard. Run off once, then COMET_STREAM_STATS=1; include raw log timestamps from boot through cut and at least 120 s after, capture at cut start/middle/end and 120/300 s using existing capture switches; note frame count and scene wall-clock times. Preserve all seven old warning lines and sequence-correlated N8 lines. Use existing debug summary if necessary for staging_waits/reading_workers. Provide G6/N5 concurrent texture due/resident slots and LOD draw capture. Interpret:
- low submitted/s, no waiting, few busy => title producer/pacing or not demanding content; compare enqueued vs submitted to isolate queue flush delay. Neither proves why the title issues too few requests.
- sustained waiting, high worker occupancy and high latency => HLE/IO/decode/map cost; high staged/limit plus low occupancy => staging throttling/queue priority, inspect before widening.
- many completed/s and published statuses with low ready-polls => title consumption cadence possible; high completions and ready polls but detail absent => GPU upload/residency, alias visibility, LOD or data integrity.
- repeated failed physical pages without matching reread => prioritize physical publication fix; distinguish unknown page vs host map vs commitment, never blindly retry a freed page. Coordinate N6 before retry changes.
