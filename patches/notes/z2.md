Base: 5c79329b51cf5915a17d43cb63dd5638381ceda3; issue #140, Z3 #139, FPS #128. Source blob list.rs b8a5c21c1bf25a8f3ecea86109c0070e9c040301, queue.rs e9cbd7d2b9a0ef673111f32223539ab54e925da8. Only staged patch and note, no CREDITS.md edit.

## Evidence and recipe

Upstream [3a99ee6](https://github.com/avatarmanz/VIctory-7900XTX/commit/3a99ee610cc706d0e7a28dde6a4f5d82303ce70f) introduces VICTORY_THIN=1 (off by default). docs/findings.md reports 75 -> 68 ms/frame, 36k list calls and 230 ms aggregate CPU/frame on 8 translator threads on RX 7900 XTX. Not our measurement, and its 7 ms gain is not additive to Z3. Current owner evidence ~160 ms prepare, 600 ms GPU wait, 100-170 ms readback; reducing recording only addresses CPU overlap.

## Implementation / limits

COMET_THIN=1 only. No shader cache change (no translated shader changes). Typed Call enum rather than copying upstream word stream. Copy inputs that the API consumes synchronously, leave data the GPU consumes at execution to existing State/HostList path. This first slice does not implement the upstream independent front/back lists, early abandonment, full vtable coverage, or async submit. A title must preserve pipelines, descriptors/heaps and referenced resource/mapped memory through recording/submission, as the original code assumes; delayed CPU reads of mutable title memory and worker-specific runtime assumptions need measured validation. Eager boundaries deliberately retain existing descriptor/copy/wait handling and may constrain speedup. Close returns the same S_OK as current implementation after scheduling; submission/reset/release wait for all replay, including close. Panic is a fatal host error rather than submitting partial work. If all worker spawns fail, fall back to original path.

## Validation

Build gate: cargo test -p comet-gpu --lib -- --test-threads=1 (Windows), then both CI Clippy modes. Tests cover single-ready/FIFO/reschedule and owned argument copy; no build/run in this environment. Check git apply --check against main (diff generated from exact fetched sources, not locally checked by git). Run matched baseline and COMET_THIN=1; keep Z3 off initially; same shader cache/camera and capture timestamps. Expected logs: COMET_THIN list translator pool (started=8), COMET_THIN recording stats every >=5s with queued, replayed, indirect, batches, worker_ms, drain_ms. Require nonzero replayed/indirect and no steadily increasing queued-replayed backlog; cumulative worker time is not frame wall time. Compare title recording-thread CPU, frame median/p95, prepare/wait/readback and draw drops; seek measurable recording overlap, not an invented FPS target. Match cell and boat captures, black albedo/geometry/texture-wait/drops/device errors and W5 ordering. Test reset/release before submit, short lists, wait cuts, duplicate list names, repeated submit, no host GPU and worker spawn failures. Reject if stale descriptors, hangs, corruption or dropped work. Then jointly test Z3; keep default off until benchmark owner accepts.

Known limitation: this is a bounded first port, not the full upstream THIN+behind architecture; the remainder requires front/back generation ownership with exact descriptor and upload semantics and coordination with Z3.
