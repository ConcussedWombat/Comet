Query due normally, then a bounded future-due window only for exact bake hashes, preserving write generation and queue ordering; dedup by (heap,slot,generation), current-due first. Convert upstream frame horizon to Comet queue clock (33 ms ticks if enabled; distinguish clock mode and avoid treating 12 ticks as 12 slow frames). If cannot prove, keep skip optimisation separate/off. Use existing 192 MiB/room caps and total budget, same-list barriers, show-after publication only once upload ordered. No blanket SRV transition, descriptor rewrite or global upload flood. Test near-future dedup, clock conversion, generation change during selection, aborted/capped pass not marked served, no cross-list publication before fence.

**Expected log:** upstream string (source, not observed Comet) "a draw of the title's decoration bake: textures picked by index are uploaded first (VICTORY_BAKE_TEXTURES_MS=0: not)"; existing Comet "M4 decoration bake texture preflight recorded". **Risk:** delayed first world, 8 GB pressure, incorrect publication across recorded lists, read during title remap; excessive stalls from future-due scans. This is a recipe for exact source freshness, not a confirmed visual fix or speed gain for this card. If actual eye/hair shading uses no affected bake, abandon attribution.

## 2 — Faster recheck when an unannounced write is found (D; E verifies colour)
**Reference:** same avatarmanz SHA draw.rs:111–120,2257–2291,2555–2563. VICTORY_RECHECK_SOON sets again_in=1 only after fingerprint mismatch; ordinary unchanged recheck backs off through RECHECK_FRAMES. Comment says repeatedly-painted aliased pages were shown four frames late. 
**Comet:** draw.rs:2410–2445,2600–2607; descriptor/host.rs:1186–1219, texture.rs:1117ff. Current mismatch path increments rechecked and reuploads but schedules first check at tick+RECHECK_FRAMES[0]. Existing N5 incomplete fingerprint sentinel preserved.
**Recipe:** default-off one-short-interval followup after a *complete* fingerprint changes and successful full upload. Preserve normal backoff for unchanged, partial, remapped, denied and new slots; guard generation and queue clock. Under clock mode use a bounded tick interval, under frame mode one frame; avoid infinite busy recheck on remapped data. No change to fingerprint algorithm or budget. Reuse N5/R3 upload ownership, no duplicate queue entries. 
**Expected log:** existing Comet recheck change log in draw.rs:2440ff plus proposed "G2 recheck soon" (slot, write, old/next tick, complete=true, source frame, upload ordered); same material pixel and successive texture fingerprints. Count reupload MB, queue age, prep ms, frame time and visual temporal staleness. Risk: churn/redundant copies; do not enable without measured latency/accuracy gain and no FPS regression. Not a substitute for one-shot bake before draw.
