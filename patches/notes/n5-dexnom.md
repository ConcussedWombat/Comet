## Benchmark / constraints
Default-off independent switches; benchmark owner A/B baseline with same mip skip, raw mirror, recheck and scene. Compare each then combined, keep first frame and 120/300 captures, 5-minute waiting (total/due/partial/away), recovered interior count and bytes, sparse scheduled partial count, remap overflows/rescan size, new/retry serviced, texture pass phase ms, local VRAM/budget, CPU/GPU time/fps and black albedo. Capture shader/slot/address for visible City textures if recovered. No new admission past room(), no forced mip promotion, no destructive residency changes. These recover work wrongly skipped/starved or invalidations lost; they do not solve physical VRAM capacity alone. Actual texture data can only be uploaded when retained mip span contains usable bytes; a positive guest-span observation does not guarantee retained mip residency. No build/game run by N5; stage source diff only. Test sparse VirtualAlloc interior/tail/empty and guard-safe behavior, producer overlap/overflow, queue first-look fairness and write-generation tests. ## Stage 3 remaining-wait diagnosis (batch 1)

Owner reports ~4,000 slots still waiting at seven minutes. Existing census (descriptor/host.rs:605 at 96dc0df) conflates retry with absent mapping (looks > 0 includes other causes and post-upload rechecks); draw.rs:2104–2111 can break before servicing a selected slot, and :2197 full-card gate leaves a slot due. A queue length or a zero working-set sample cannot prove permanently unmapped.

Staged patches/n5-wait-reasons.patch.txt 72b78f7 (original Comet diagnostic, no imported code, no CREDITS.md edit), COMET_N5_WAIT_REASONS=1. Every 10 seconds per view heap on the existing heap pass, log "N5 waiting texture reasons": current waiting, old (>=120s since this write/invalidating notification), never_attempted (old and due, no entry passed time/byte limit), never_rechecked (old and due, exactly one actual attempt), overdue_retry (old, due, >=2 attempts, last >=15s ago), persistent_unmapped (>=2 whole-span reserved/free observations separated by >=120s, latest within 20s, no intervening positive observation), last_verified_unmapped (less stringent), mapped_seen (ever saw mapped/committed on current generation), recheck_pending, recheck_due_unseen (whole-upload recheck due but zero successful unchanged looks), partial, room_refused (last attempt), no_exact_observation, and up to 8 example (slot, write generation) identities per absent/unserviced class. Counters overlap; not a partition. 'Persistent' is observed only, not forever/continuous; descriptor rewrite/remap notification resets the generation. No inference of absence when size unknown, mapping pin unavailable, query fails, or exact query cap skipped. A committed guarded/noaccess page disproves wholly unmapped, not necessarily readable. Uses existing fast residency then at most 32 nonblocking whole-span VirtualQuery walks per pass for zero observations (per slot >=10s between successful exact observations), under range pin; diagnostics do not create or null any resources or modify scheduling. Counts may understate absence if scheduling itself starves probes; inspect no_exact_observation. Extra per-entry metadata and locks/queries are diagnostic overhead, not a production optimization. Unit test covers first vs retry, wall-time thresholds, expiration, positive reset and generation reset. No local build/test.
