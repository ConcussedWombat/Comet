Do not transfer the shirt's lighting diagnosis to decals without a matched sample. No specific poster PS hash is available; the fix below is a source-grounded compatibility candidate, not a confirmed poster correction.

Known non-decal-identified pair: mesh f5e50eb2108c425b / pixel ce3f0432a08f1d35. Belobug's 8629211 commit explicitly associates it with the first room's walls, an R8_UINT MRT and E_INVALIDARG; #72 identifies the same pair in Comet. Integer blend cannot fix that error; do not use this pair as proof of a decal or promise it will now compile.

## Single staged experiment

Normalize title blend for active integer RTVs only (integer, not UNORM/SNORM/float). Determine effective common or independent entry before changing anything; split common state into copies only if required, then clear BlendEnable on affected entries. Preserve write masks, factors, operations, logic op state, alpha-to-coverage, and all color targets. Both graphics and mesh (including R4 canonical blend retry) use effective blend. Append a PSO library state suffix only when the changed mask is nonzero; no translated shader bytes changed, so no shader cache key modification. Log `Z10 integer RTV blend normalized` with exact shader stage hashes, target formats, mask, original/effective descriptors. This is a predicted marker, not an observed line. Follow it with host graphics/mesh accepted/refused and actual draw. No pixel rewrite, skipped draw, alpha forcing, texture substitution or global blend disable.

Two unit tests exercise mixed formats, common/independent blend, full entry preservation including write masks, unused formats, and already-unblended entries. Five unified hunks verified against exact source contents and line counts via connector; latest read confirmed same source blob. No local Git checkout/network, Windows build, game run, git apply executable verification, or GPU results. Build gate compile/lint/test and reviewer required; user-visible improvement unmeasured.
