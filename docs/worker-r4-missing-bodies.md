## Candidate A: first-use producer recovery

[worker-r4-geometry-first-use.patch.txt](worker-r4-geometry-first-use.patch.txt) ([0bb5c6a](https://github.com/Fyntra-Development/Comet/commit/0bb5c6a01f26ce0f469fad5e82c5f93d2373e238)), changes only pipeline/make.rs. COMET_R4_GEOMETRY_TRACE=1 logs first-use compilation misses and later request resolution by exact PSO key and shader hashes. COMET_R4_GEOMETRY_WAIT=<comma-separated 16-digit hashes> prewarms selected producers/draws at creation and, on their first request only, gives them a bounded extra shared wait if the regular budget expired. COMET_R4_GEOMETRY_WAIT_MS defaults to 250, capped at 500; unset/empty hash list leaves normal behavior. No synchronous/unbounded compiler wait, no shader substitutions or bypass of refused PSOs. Extra time may hurt loading and first-world frame; test only selected implicated producers. Test covers exact hash parse, shared reservation, same-frame refunds and stale-frame rejection. Evidence: older diagnostic run reports 4.0 and 4.5/frame dropped for "being made" at 03:04:04 and 03:04:10, then zero in later intervals. A one-time skinning/LOD producer missed at startup can leave its buffers uninitialized even after the host pipeline finishes, but this has not been established for the beach body. No reason to expect a steady-state drop-count gain from this candidate. With tracing on, select only a first-use miss tied to the affected geometry; if no relevant miss exists, do not enable the wait. Expected metric for selected recoverable misses: R4 geometry first use missed -> zero, and corresponding "dropped ... without a host pipeline: being made" reduced by the number of restored first-use operations. ## Prison yard triangle and floating sky boxes

Capture a local frame with the artifact visible, and correlate the output target with its list and exact graphics-stage hashes using the existing frame op listing. Start with the normal (all probes off) capture. If a graphics mesh/vertex candidate is found, repeat the same scene with only COMET_R4_WIREFRAME set to that full hash. If the filled triangle becomes edges or boxes become outlines, the anomaly is rasterized by that selected PSO; if it remains filled, examine other contributing PSOs or a later lighting/composite pass. This probe does not prove bad positions versus incorrect depth/coverage, and may affect many objects sharing that shader. Revert after identification. Existing diagnostic COMET_SKIP_PIPELINES can isolate a suspect **graphics-stage** hash separately (never skip skinning/culling producers as a correctness fix); the suspect skipped counter will rise by design, not a speed gain. Avoid global mesh skip and keep normal depth tests enabled.

Priority order once isolated:
1. Determine if the offending draw is vertex/indexed or mesh. Verify input layout/format, index count/start/base-vertex, stride and actual initialized/resident bytes. For mesh, compare group counts and per-meshlet vertex/primitive counts, indices and positions; check producer output and consumer root/heap resource ranges.
2. Current lower.rs mesh_prologue uses declared maxima in place of actual allocation counts and initializes unused primitives as degenerate triangles. emit_indices rejects indices beyond declared/lanes limits, but that does not prove referenced in-range vertices actually wrote a valid SV_Position. This is a concrete hypothesis for an oversized triangle if the wireframe test identifies a mesh PSO. Verify against the specific native/translated mesh hash; do not remove the initialization or bounds blindly. Check finite clip-space coordinates (including w), actual valid written vertices and primitive cull flags. Floating boxes may be incorrect LOD/bounds geometry or stale vertex/instance transforms, not necessarily the same shader.
3. The indirect clamp bounds counts, not vertex/index/instance address contents. A plausible count with stale arguments can still produce bad geometry. Check argument producer, record offset, start/base index and residency; compare before/after selected producer recovery. Do not raise global safety limits.
4. If wireframe finds no rasterizer candidate and the boxes appear only in a lighting/post-processing target, hand the actual producer hash to R2; do not assume geometry or lighting without attribution.

Expected diagnostic metric: R4 geometry rasterizer probe reports the selected shader and mode; actual draw/dispatch counts and dropped-pipeline reasons should remain unchanged in a wireframe/cull comparison. Expected visual outcome for the responsible hash: offending filled triangle/boxes become outlines in wireframe. A confirmed geometry fix must eliminate them **with all probes unset**, restore missing limbs/terrain, preserve valid mesh output and avoid new drops. No new numerical drop reduction claimed: previous PSO recovery target remains 5–6/frame if all five are accepted. R1 / draw-resource and shader owners: capture/verify actual buffer and output data for the identified hashes; R4 scope remains pipeline creation.
